# UI 设计尝试 02：留一个开口

本次是新的可修改尝试。遵循用户已认可的「少文字、第一眼找到重点、轻松开始」，不覆盖长期产品约束。

## 1. 随机来源

Shell 从 `/dev/urandom` 读取 1024 字节，经 `od` 与 `tr` 生成 2048 位十六进制字母数字串。字符取自 0–9 与 a–f，来自系统随机源。原串不写入 HTML，不作为界面内容。

## 2. 从字符到视觉

- 连续的 00、88 呈现成对闭合结构：转译为品牌的两枚细线环，相邻但留有开口。装饰只在桌面边缘出现，不抢占输入区。
- fff 和密集数字段形成深浅节奏：用石墨黑承载标题，灰色承载说明，把唯一主动作赋予高显著性的橙色。色值是审美转译，不声称随机字符客观代表某种颜色。
- 等宽排列与字符变化并存：采用严格中轴、对齐边界及细线分区；正文用自然的无衬线字体，只有流程序号采用等宽。
- 成对字符与不规则断点：以两行标题、单张白色输入卡和下方分开的两块轻量信息区，建立「聚拢—停顿—开始」的阅读节奏。

唯一视觉灵感来自本次随机串；产品文案与功能边界来自 PRD 和用户要求。

## 3. UI 规范

- 背景：暖灰白 `#F4F3EF`；主文字：石墨黑 `#282824`；主按钮：橙色 `#F15C35`；边框：`#DDDDD4`；输入卡：纯白。
- 字体：Arial、PingFang SC、Microsoft YaHei 系统无衬线。桌面标题 68px、大屏 76px、手机 43px；正文 12–16px；输入正文桌面 16px、手机 14px。使用字重与留白建立层级，不引入外部字体。
- 桌面：输入区最大宽度 660px，居中；左右只保留克制的线条装饰。白卡细边框、轻微底层阴影、橙色按钮建立唯一主视觉。
- 手机：隐藏边缘装饰，标题和输入左对齐，按钮全宽，快捷例子紧跟输入。无悬浮重复操作条。
- 首屏文案：一句价值、一个输入、一个主按钮。分享入口为次级动作；身份、回复和等待说明折叠在下方。

## 4. 本次实现范围

文件 `landing-experiment-02.html`，保留前版用于比较。输入、快捷填入、目标经历确认及分享经历弹窗是本地预览，不保存内容、不进行真人匹配、不声称完整 PRD 已实现。键盘可操作、弹窗支持 Escape，遵守减少动态效果偏好。
